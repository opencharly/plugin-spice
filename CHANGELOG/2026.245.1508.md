# 2026.245.1508 — fix(spice): capture every poll as a frame (multi-frame MJPEG video semantics)

## Summary

Fixes a recorded-vs-intended divergence in `spice: record` (merged in #4): the CHANGE-ONLY capture produced exactly **1 frame** over a short interaction window — a single JPEG still, not a multi-frame MJPEG video (measured on the R10 spike, calver 2026.245.1423: frames: 1 — a 3s desktop window renders one damage event and an idle window none). **Video semantics require every poll at fps to be a frame** (static displays repeat frames — that is normal video). This change removes the change-detection skip (`framesChanged` + the `rs.last` field and its test deleted, R5) so `record: stop` produces a true multi-frame stream; the artifact validators + host `ffprobe` frame count then honestly assert a real capture.

**Changes:** record.go — the poller appends every tick's framebuffer (no change detection); the now-dead helpers removed; unit tests updated (TestFramesChanged deleted; the MJPEG split/decode tests remain).
