# 2026.254.0449 — refactor(spice): route artifact validation through sdk.LandArtifact

## Summary

Migrates plugin-spice's artifact handling from the hand-rolled validator leg (a direct `sdk.RunArtifactValidators` invocation folded inside `sdk.VerbVerdict(..., artifact=true)`) to the single entry every capture plugin uses: `sdk.LandArtifact` (sdk#249, sdk v0.2026254.439).

spice is a HOST-side producer — the screenshot/cursor PNGs are written by the plugin's own display decode (methods.go `runScreenshot`/`runCursor`, record stop flushes the MJPEG stream), never pulled from a venue — so this migration is the validate-only leg of LandArtifact: the provider calls `sdk.LandArtifact(ctx, nil, "", in.Artifact, &op)` (nil executor + blank venue path → no pull, no write, validate the existing file in place), and `sdk.VerbVerdict` now runs with `artifact=false`, the exit/stdout/stderr matchers split from the artifact leg.

The pixel write itself stays where it is — the plugin still produces the file; it just stops hand-rolling the validator call. Error surfaces unchanged: the artifact-failure message keeps the exact `spice: <method>: <err>` shape the VerbVerdict artifact block produced.

Also bumps:

- `github.com/opencharly/spec` rides to v0.2026250.2036 (`go mod tidy`, the new sdk's required baseline)
