# 2026.314.1321 — refactor(schema): derive the spice word sets from vocabulary tables

## Summary

Convert the three inline `|` word unions in `candy/plugin-spice/schema/spice.cue`
to the §10.1 S3 vocabulary-table idiom, so each closed set of words has ONE home
and the enum an author meets is `or()` of that table's keys:

```
_method  _action  _consoleAction
(+ _methodWord / _actionWord / _consoleActionWord)
```

That is the 3 `union` rows `design/dpat-baseline.tsv` records for
`plugin-spice/candy/plugin-spice/schema/spice.cue` — three disjunctions, one row
each, all three pure word lists.

**The one judgement this repo needs: two of the three sets are fields named `action`, and
they are DIFFERENT vocabularies.** `#SpiceInput.action` is a record/session action
(`start|stop|status`); `#SpiceConsoleStep.action` is a console step's
(`key|type|key-combo`). Merging them into one table would be the obvious sweep and the
wrong one: a step could ask for a record session with the action `key-combo` and a console
step could carry the action `stop`, and both would validate here and then fail — or do
nothing — at dispatch. They get two tables, and `TestTheTwoActionSetsAreDistinct` pins that
each field REFUSES the other's words.

**How this repo was picked.** It is the third unit of the sequence, from the
entirely-word-list set re-derived in the first unit:
