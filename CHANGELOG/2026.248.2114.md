# 2026.248.2114 — fix(spice): session threads log_dir on every op + stop waits (bounded) for the evidence row

## Summary

RCA (live, check-instrument-cachyos-vm): the instrument lifecycle's spawn threaded the run dir over the wire (buildInstrumentOp's log_dir), but sessionStart hardcoded logDir := "" — the runner's handle landed in the cwd-relative capture/<id>/ instead of .check/<bed>/<calver>/capture/<id>/, polluting the repo root and breaking the evidence envelope's handle lookup. The stop/status ops sent no log_dir either, so once the spawn-side fix moved the handle into the run dir, the stop looked in the default and found "no session on record".

- sessionStart: thread in.LogDir into the spawn request (the A-task-4 instrument lifecycle already provides it; a plan-step session falls back to the runner's cwd-relative default).
- sessionStop/sessionStatus: thread in.LogDir too — the runner resolves the handle under the run dir the spawn used.
- sessionStop: wait (bounded, 10s) for the evidence row after the stop op — the runner's stop ladder bounds the process exit, but the recorder's finalize is its own SIGTERM trap and can lag the exit (a blocked display poll); a stop that returns before the row is on disk is a false failure.
