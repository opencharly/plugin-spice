# 2026.267.2318 — feat(spice): the wizard method — the console engine over the SPICE transport

## Summary

Adds the `wizard` method to the `spice` verb: drive a text-console wizard (an OS
installer, a first-boot provisioning flow) on a VM's SPICE console, OCR-gating
each screen. It is the SPICE sibling of `plugin-jetkvm`'s `install` driver — the
SAME engine and the SAME recipe drive either transport (R3).

### `spice: wizard`

- Inline `steps:`, or a `device:`/`recipe:` reference to the transport-neutral
  console-recipe entity (the generic `kind: jetkvm` entity BOTH transports read).
- Answers merge through the shared `kit.MergeAnswers`: `answers_env` (host
  environment) then authored `answers`; recipe selection through
  `kit.SelectRecipe` (incl. the bare `steps:` shortcut).

### The engine is `sdk/kit`'s (R3)

`sdk/kit`'s transport-agnostic `ConsoleWizard`/`ConsoleStep`/`ConsoleTransport`
(opencharly/sdk#276, tagged `v0.2026266.2315`). `console.go` supplies only the
SPICE transport (`Capture`/`PressKey`/`PressCombo`/`Type`) over the existing
`SpiceSession`, plus the out-of-process recipe-entity resolution (loaderkit over
the reverse channel — the same `deploy-plugins-connect` seam `plugin-jetkvm`
uses). The pin moves to `sdk v0.2026266.2315`.

### The authored shapes are CUE-sourced (SDD)

`schema/spice.cue` gains `steps`/`device`/`recipe`/`answers`/`answers_env`, the
neutral `#SpiceConsoleStep`, and `#SpiceConsoleRecipe`/`#SpiceConsoleRecipeEntity`,
generated into `params/cue_types_gen.go`. There is NO hand-written wire type: an
earlier draft carried a `credentialGetInput`/`Reply` mirror for an `answer_secrets`
credential lookup; that whole feature is REMOVED here (the env path is the secret
channel), so the plugin ships no non-compliant wire shape.

### Other changes in this diff

- `recorder.go`: `writeFrames` now returns a writer error and `captureSession`
  surfaces it (R1 zero-warnings).
- `console.go`: the transport timings are NAMED constants (`readinessWait`,
  `chordHold`) with doc comments — readinessWait is the async channel's bounded
  readiness poll; `chordHold` is the SPICE transport's own chord-hold.
- `charly.yml`: the schema stamp migrates to `2026.261.1747`.
- `session_test.go`: a trailing blank line removed (whitespace-only).
- `provider.go` + `methods.go`: `provider.go` now obtains the reverse-channel
  executor once (`sdk.ExecutorForInvoke(ctx, req.GetExecutorBrokerId())`) and
  threads it into `dispatch`, whose signature gains the `*sdk.Executor` — the
  seam `runWizard` needs to resolve a `device:`-referenced recipe entity.
- A real bug surfaced while testing: `spiceKeyNameToScancode` had no letter keys,
  so the Omarchy `ctrl+c` combo failed with "unknown key". Added `a`-`z` + `0`-`9`.
- `go.mod`/`go.sum`: the `sdk` pin moves to `v0.2026266.2315` and `spec` to
  `v0.2026266.1044`; the transitive indirects those bring in
  (`opencontainers/go-digest`, `opencontainers/image-spec`, `golang.org/x/term`,
  and the `x/net`/`x/sys`/`x/text` version bumps) plus the `plugin-egress`/
  `plugin-init` module sums are all resolved from the proxy by `go mod tidy` — no
  direct dependency was added.
