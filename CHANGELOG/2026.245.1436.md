# 2026.245.1436 — feat(spice): add the record method - host-side MJPEG video capture of the SPICE display

## Summary

Adds the `spice: record` method — host-side MJPEG video capture of a VM's SPICE display channel. `spice: {method: record, action: start, fps}` polls the SPICE session's MARK-stashed framebuffer at the configured rate, encoding each CHANGED frame as stdlib JPEG into a single MJPEG stream; `action: stop` flushes it to the host artifact where the shared artifact validators run (`artifact_min_bytes`). Sessions are package-global by `record_name` and survive across check steps (the plugin process serves the whole check-live run; holding the SpiceSession keeps the wire + framebuffer alive).

Pure-Go (cgo-free; image/jpeg already in the vendored lib graph). **Limits documented in code + candy text:** the vendored SPICE client cannot decode server video streams (SPICE_MSG_DISPLAY_STREAM_*) or GLZ/PLT images (motion-heavy guests may freeze where the server switches to streams); audio impossible (stubbed channels). MP4/webm containerization is a host-side ffmpeg post-pass (R3).

**Changes:** schema (`method: record` + `action`/`record_name`/`fps`), record.go (session registry + fps poller + change-only JPEG capture + MJPEG writer), methods/provider wiring, unit tests (naming, fps default+cap, change detection, MJPEG split + per-frame decode).
